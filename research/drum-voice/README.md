# Drum VoiceCtl lifecycle, rev246

Since 0.53.0 the selection helper is shared with `Source/Drum246Allocator.h`
and integrated through an explicitly authored host adapter. The remaining
models in this research directory are not linked into the instrument; version
0.52.0 references below describe the initial study. See

Research-only reconstruction of the original note-on/off consumer of Core drum
activity. Not linked into the instrument; version stays 0.52.0. See
[the contract](../../docs/drum246-voice-lifecycle.md) and
[numeric evidence](../../docs/firmware/drum-voice246-validation.json).

```sh
cmake -S research/drum-voice -B /tmp/drum-voice -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/drum-voice --config Release
ctest --test-dir /tmp/drum-voice -C Release --output-on-failure
```

Python 3 decompresses the two numeric gzip fixtures into a temporary directory.
A C++17 executable compares every output record. Original firmware, ELF,
disassembly and decompiler output are kept outside the checkout.

## Reproduce privately

```sh
python3 scripts/verify-drum-voice246.py \
  --ldr /private/OP1_vdk.ldr \
  --assembler /tools/bin/bfin-elf-as \
  --linker /tools/bin/bfin-elf-ld \
  --simulator /tools/bin/run-fp \
  --testutils /tools/src/sim/testsuite/bfin \
  --output /private/new-drum-voice-run
```

Requires all three [simulator writeback fixes](../blackfin/README.md). Both
probes run before firmware instructions. Output must be new and outside the
checkout. `--record` explicitly replaces fixtures; normal mode compares numeric
bytes against the committed fixtures. The PCM/control prefix is generated by
`verify-drum-core246.py`; no private file beyond the supplied LDR is needed.

## Numeric format

Little-endian fields. Prefix: eight PCM banks of 1,056 signed halfwords each
(16 zero guard halfwords, 1,024 samples, 16 guards), then eight sounds × 24 pads ×
eight control halfwords: 19,968 bytes total, matching the Core routing fixtures.

Input record: 1,156 bytes. Six words: flags, selected sound, factory sound,
render/query voice, signed octave transposition, signed preview pad. A four-word
note event follows (note, velocity, byte metadata in a word, payload). Then twelve
20-byte sampler states (240 bytes), twelve busy bytes, twelve owner words,
twelve pad words, 128 pitch words and 128 gain halfwords. Flags: reset=1,
preload pool/busy/owner/pad=2, note-on=4, note-off=8, render=16, activity query=32.
Reset supplies zero globals, drum mode 1, empty held count with `0x5a` row padding,
and a sampler factory; the explicit preload follows. Controls stay fixed for
the run. The harness supplies preview, selected sound and event timing.

Output prefix: 1,025 original FIR halfwords and two padding bytes (2,052 bytes).
Record: query return (4), full sampler pool (240), globals
`0xff801038..0xff801363` (812), held-list backing storage and count (2,564), audio
(256), pitch (512), gain (256), derived gain (512): 5,156 bytes. Query skip keeps
`0x13579bdf`. Audio poison is alternating `0x1357/0x2468`; derived gain starts at
`0x6c6c6c6c` and persists over skipped renders. Suffix: all 16,896 PCM bytes,
checked unchanged. State/list/global images persist between events, with 64
explicit fresh scenarios of 64 events each.

The original complete note-on/off callbacks and Core activity query run unpatched,
with real original sampler methods; the optional renderer is called by the
harness at a supplied cadence. The model's selected-voice return is a diagnostic:
the original note callback is void. Only five exact octave transpositions
(-24/-12/0/12/24) are covered. Modulation objects and FX are explicitly null.
No original gain/pitch buffer producer, render scheduler, MIDI receiver, D-box,
acoustic equivalence or live plugin integration is claimed.
